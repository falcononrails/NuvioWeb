# Local audio playback

Native browser/HLS/DASH playback remains the first choice. For direct files with unsupported audio, playback tries AVPlayer before allocating a server conversion session. It also uses this path when changing an audio track that the browser does not expose. An empty audio-track list alone is not evidence of silent audio.

AVPlayer 1.3.1 supplies audio to the existing video element through a MediaStream. Video stays on WebCodecs; AC3, EAC3 and DTS audio can use the bundled WASM decoders. JavaScript and decoder files load only when recovery is needed. Supported browsers need WebCodecs, AudioWorklet and MediaStream. A startup/decoder/network failure falls through to the existing authenticated server path once. Stopping or replacing playback cancels the attempt.

The controller uses AVPlayer's media timeline for seeking, resume, duration and watched progress. The preferred audio language is selected before attaching the MediaStream; an explicit track choice takes priority. Audio changes flush queued packets by seeking back to the same position. Volume, mute, controls and picture-in-picture still use the video element.

Embedded text subtitles are listed alongside addon subtitles. Selecting an embedded track uses the authenticated playback service to extract a bounded WebVTT window, then renders it in the existing HTML overlay against the original media timeline. This also works during server conversion and native file playback when browser subtitle tracks are unavailable. Seeking refreshes the window; switching to an addon or Off discards pending results. Existing subtitle delay and presentation controls still apply.

After server conversion, the clock is mapped from the first source video packet to its converted timestamp. This accounts for a seek starting at an earlier keyframe and keeps subtitle timing and resume progress aligned with the video.

Extraction reads source bytes but does not decode/re-encode video. It requires the playback service and remains subject to its file, account and concurrency limits. Each selected-track window is limited to 125 seconds of media, 20 seconds of extraction time and 2 MiB of output; active conversions allow one subtitle extraction at a time. Text formats include SubRip, ASS/SSA, WebVTT and MP4 timed text. ASS styling is normalized to the app's subtitle style. Image subtitles such as PGS/VobSub need an external player or an addon subtitle. Subtitles rendered in the page are not burned into picture-in-picture video.

Local decoding does not bypass CORS, HTTP 403 responses, expired URLs or DRM. It does not enable software video decoding on devices without a supported WebCodecs video decoder. Server fallback retains its account and resource limits.

## Checks

```sh
npm ci --ignore-scripts
npm test
npm run build
node scripts/generate-subtitle-fixture.mjs /path/to/synthetic/fixtures
node scripts/local-audio-smoke.mjs /path/to/synthetic/fixtures
# Serve the generated MKV on a public test host, then run with FFmpeg installed:
NUVIO_SUBTITLE_FIXTURE_URL=https://example.org/embedded-subtitles.mkv node --test services/playback-bridge/embedded-subtitles.test.mjs
```

The browser check uses installed Chrome and Playwright, with no autoplay bypass flag. Its fixtures are generated by the [AVPlayer benchmark scripts](https://github.com/falcononrails/NuvioWeb/tree/feat/avplayer-benchmark/scripts/benchmarks/avplayer). It verifies audio tones, track changes, the media timeline, pause/resume, seeks, subtitle timing, speed, source cleanup, cancellation, server fallback and automatic recovery through the player UI. The server response is simulated HLS; the test does not require an account or reserve production slots.

Desktop Chrome is verified. Real iPhone/Safari, Android and Xbox behavior still needs device testing. See the benchmark report for the measured timing and CPU limits; local decoding is not a guarantee that every file plays on every device.

## Library assets

The build copies the pinned `@libmedia/avplayer` UMD files unchanged. Audio WASM binaries are vendored under `assets/libs/avplayer-wasm-1.3.1`, with their license, source revision and build-recipe link. No third-party runtime CDN is required for this fallback.
